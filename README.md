# Leave Management System (LMS)

A full-stack web application for managing employee leave requests. Employees can submit and cancel leave, and managers can review and approve requests — all through a clean, role-aware interface.

> **This implementation was entirely generated by [PostQode](https://postqode.com).**

---

## Overview

LMS is built with a **React** frontend and an **ASP.NET Core** minimal API backend. It demonstrates a clear separation of employee and manager workflows, leave balance tracking, and request lifecycle management (Pending → Approved / Cancelled).

**Key capabilities:**
- Submit leave requests with start and end dates
- Track remaining leave balance in real time
- Cancel pending requests
- Manager approval flow with balance validation
- Role switcher for toggling between Employee and Manager views

## Getting Started

### Prerequisites

- [.NET 10 SDK](https://dotnet.microsoft.com/download)
- [Node.js 20+](https://nodejs.org/)

### 1. Start the backend

```bash
cd backend
dotnet run
```

The API will be available at `http://localhost:5000`.

### 2. Start the frontend

```bash
cd frontend
npm install
npm run dev
```

The app will be available at `http://localhost:5173`. The Vite dev server proxies all `/api` requests to the backend automatically.

## API Reference

### Health

| Method | Endpoint       | Description  |
|--------|----------------|--------------|
| GET    | `/api/health`  | Health check |
| GET    | `/api/shell`   | Navigation and role config |

### Employee

| Method | Endpoint                                      | Description                  |
|--------|-----------------------------------------------|------------------------------|
| GET    | `/api/employee/balance?employeeId={id}`       | Get leave balance            |
| GET    | `/api/employee/leave-requests?employeeId={id}`| List leave requests          |
| POST   | `/api/employee/leave-requests`                | Submit a new leave request   |
| POST   | `/api/employee/leave-requests/{id}/cancel`    | Cancel a pending request     |

**Submit request body:**
```json
{
  "startDate": "2025-08-01",
  "endDate": "2025-08-05",
  "employeeId": 1
}
```

### Manager

| Method | Endpoint                                         | Description                 |
|--------|--------------------------------------------------|-----------------------------|
| GET    | `/api/manager/leave-requests`                    | List all team leave requests|
| POST   | `/api/manager/leave-requests/{id}/approve`       | Approve a pending request   |

---

## Business Rules

- Each employee has a **baseline of 15 leave days** per year.
- Leave balance is computed from **approved** requests only — pending and cancelled requests do not reduce balance.
- Only **Pending** requests can be approved or cancelled.
- Employees can only cancel **their own** requests.
- A manager cannot approve a request if the employee has **insufficient remaining balance**.
- Request lifecycle: `Pending → Approved` or `Pending → Cancelled`

## Notes

- State is held **in memory** on the backend — it resets on server restart. There is no database persistence in this version.
- Authentication is not implemented. The employee identity defaults to ID `1`.
- The `.postqode/` folder contains configuration for the [PostQode](https://postqode.com) API testing tool.
